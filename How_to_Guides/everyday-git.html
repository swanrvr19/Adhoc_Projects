The mental model

four places your work can live

Nearly every git command moves changes between these four places, or shows you the gap between two of them. Once the picture is clear, the flags stop feeling arbitrary.

Working tree
your files
Staging area
the index
Local repo
.git history
Remote
origin
git add
git commit
git push
git fetch / git pull
git restore --staged
git reset

Read it as: add stages, commit records, push publishes — and each has a mirror that walks the change back one step. git status tells you which of the four places your current edits are sitting in.

Undo & rescue

Recipes

the sequences, not the single commands

Start something new

  1. git switch mainStart from the shared branch.
  2. git pullMake sure it's current.
  3. git switch -c feature/thingBranch off it.
  4. git push -u origin feature/thingPublish it and set upstream.

Resolve a merge conflict

  1. git statusSee which files conflict.
  2. Edit each one; delete the <<<<<<< markers.
  3. git add <file>Staging is how you say "resolved".
  4. git commitOr git rebase --continue mid-rebase.

Committed on main by mistake

  1. git switch -c feature/thingThe commit comes with you.
  2. git switch main
  3. git reset --hard origin/mainPut main back where the remote has it.
  4. git switch feature/thingCarry on where you left off.

Update a long-lived branch

  1. git fetch originGet the latest refs.
  2. git rebase origin/mainOr merge if others share the branch.
  3. Resolve conflicts, then git rebase --continue.
  4. git push --force-with-leaseNeeded after a rebase, and only this variant.
